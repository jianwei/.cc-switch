## 步骤 7.5：【新增】逐 Group 对比还原

在整体实现完成后、最终验证之前，必须对页面中的**每一个 Group 逐一进行单独截图对比与还原修正**。

### 执行方式

1. **枚举所有 Group**  
   从步骤 2 获取的设计上下文中，列出页面内所有顶层 Group（即 Figma 中的 Frame / Group / Section）。

2. **逐个获取截图**  
   对每一个 Group 单独调用：
   ```
   get_screenshot(fileKey=":fileKey", nodeId=":groupNodeId")
   ```

3. **逐个对比还原**  
   将每个 Group 的截图与当前实现进行比对，检查以下内容：
   - 内部间距与外边距是否一致
   - 子元素排列顺序与对齐方式
   - 字体大小、颜色、行高
   - 图标/图片尺寸与位置
   - 边框、圆角、阴影等视觉细节

4. **发现偏差立即修正**  
   每个 Group 对比完成后，若发现还原偏差，**立即修正当前 Group 的代码**，再继续下一个 Group，不得积攒到最后统一处理。

5. **记录每个 Group 的对比结果**  
   完成后输出一份简要对比报告，格式如下：

   | Group 名称 | 状态 | 备注 |
   |-----------|------|------|
   | Header    | ✅ 通过 | — |
   | Banner    | ⚠️ 已修正 | 内边距偏差 8px |
   | Footer    | ✅ 通过 | — |

### 注意事项

- 每个 Group 必须**单独截图**，不得仅凭整页截图目测判断
- 此步骤不可跳过，即使整体视觉看起来已经接近设计稿

### ⚠️ 嵌套 Group 的坐标陷阱（重要）

Figma 中所有节点的坐标（x/y）均为**相对于画板原点的绝对坐标**，而非相对于父 Group 的相对坐标。

**问题根源：**  
当对嵌套子 Group 单独截图后，直接按 Figma 的 x/y 值还原，子元素会以整个页面左上角为基准定位，导致它"跑"到父容器之外。

**正确处理方式：**

1. **换算为相对坐标**  
   子 Group 在父容器内的实际位置 = 子节点绝对坐标 − 父节点绝对坐标  
   ```
   子元素 left = 子节点.x − 父节点.x
   子元素 top  = 子节点.y − 父节点.y
   ```

2. **优先用 flex 布局替代绝对定位**  
   若子 Group 在父容器内是线性排列（水平/垂直），使用 `flex` 表达位置关系，而非 `position: absolute`，可完全避免坐标换算错误。

3. **仅在必要时使用绝对定位**  
   当子元素存在重叠、悬浮等无法用 flex 表达的位置关系时，才使用 `position: absolute`，此时**必须**换算为相对坐标，并确保父容器设置 `position: relative`。

4. **递归向下逐层处理**  
   若子 Group 内部仍有嵌套，每一层都按上述规则换算，直到最小可见单元。截图仅用于**视觉比对**，坐标数值必须以换算后的相对值为准。

## 步骤 0：【必须】确认平台类型

**在执行任何还原操作之前，必须完成此步骤，不得跳过。**

### 规则

- 用户请求中**已明确说明**平台（如"H5"、"移动端"、"PC端"）→ 直接记录，继续执行
- 用户**未明确说明**平台 → **强制停下询问，不猜测，不继续执行**

### 询问话术

> 在开始还原之前，请确认一下：这个页面是 **H5（移动端）** 还是 **PC 端**？  
> 平台类型会影响布局策略和代码风格，所以这一步是必须的。

**在用户明确回答之前，不执行步骤 1 及后续任何步骤。**

> 💡 如果 Figma 画板宽度明显是移动端尺寸（如 375px），可在询问时附上建议，但最终仍需用户确认。

## 步骤 5（扩展版）：按平台规范转换代码

在执行 implement-design 步骤 5 的基础上，额外应用以下平台规范：

### H5（移动端）

- 布局以 `flex` + `column` 为主
- 宽度使用 `%` / `vw`，避免固定 `px` 宽度
- 字体/间距使用 `rem` 或 `vw`
- 禁止多列 `grid` 布局（除非设计明确要求）
- 图片使用 `width: 100%` + `height: auto`
- 组件单独维护，**不与 PC 共用布局组件**
- **尽量少使用 `float`**，布局问题优先用 `flex` 解决，仅在文字环绕图片等极少数场景下允许使用

### PC 端

- `flex` 和 `grid` 均可，根据设计选择
- 宽度优先使用固定 `px`
- 字体/间距使用 `px`
- 多列布局使用 `grid`
- 定义明确的最大容器宽度（如 `1200px`、`1440px`）
- 考虑 hover 交互状态
- 组件单独维护，**不与 H5 共用布局组件**
